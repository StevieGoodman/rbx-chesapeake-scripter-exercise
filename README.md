# Chesapeake Scripter Exercise
Hello!
Please take your time to read this description of this exercise.

You will have 2.5 hours to complete this task, beginning from the first line of code you write.
You may use any code or assets made available to you in the `studio.rbxl` file inside this directory.
You may not import any other scripts or assets, but may create your own. The code provided uses Chesapeake's own framework, but feel free to create your own if you believe it would be better suited to the exercise at hand.
If you are unfamiliar with any of the libraries provided to you, you may conduct research on them before beginning this exercise.
Our preference is that applicants use the framework provided, using Knit for abstract behaviours (such as permissions) and Component, in combination with Comm, for instance-specific behaviours, such as pressure plates, rotating lights and tools. However, you will not be penalised for creating and using a suitably designed framework.
You may program in either the native Studio client (Chesapeake's preferred workflow), or use Rojo (in combination with this file's directory) in tandem with an IDE or text editor of your choice.
The description of the exercise is kept deliberately vague to allow for interpretation, so you may approach each task in whichever way you believe is best.

## The Exercise
You should create a simple prototype for a 2-team capture-the-flag style game. You must:
1. Allow flags to be picked up by players
2. Allow flags to be delivered to a team's base
3. Keep track of the score for each team, and provide an API for this data to be accessed
4. Display each team's score in the provided GUI
5. One extra feature to make the submission your own

With any remaining time left, you may make adjustments or additions to the prototype so long as the above tasks remain complete.

## Submission
If you programmed entirely within the Studio file, please submit the Roblox Studio file in a reply email.
If you programmed any part of your submission within VSCode, upload the Git repository to GitHub and submit a link to the public repository in a reply email.

Whilst not mandatory, we would greatly appreciate additional insight into your decision making process during development of your submission. We encourage all applicants to describe their development process and any decisions they made in their submission email.
